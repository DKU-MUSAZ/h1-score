# 안운잘부 이용 규칙 및 게임 구현 명세

안운잘부는 운전자가 목적지까지 이동하는 동안 차량 신호와 내비게이션 정보를 수집하고, 정해진 구간의 운전 습관을 점수로 평가하는 애플리케이션이다. 운전자는 주차한 뒤 자신의 주행 결과를 확인하고, 인정된 경기와 방문 기록을 통해 배지를 모을 수 있다.

이 명세는 기획자, 개발자, 디자이너, 검증 담당자가 같은 규칙을 기준으로 협업할 수 있도록 참가 조건, 대회 배정, 점수 계산, 결과 인정, 보상 지급 및 예외 처리를 설명한다. 각 규칙은 현재 구현을 기준으로 작성했다. 아직 실제 서비스에 연결하지 않은 기능은 해당 설명에 구현 범위를 함께 표시했다.

| 항목 | 기준 |
|---|---|
| 문서 버전 | 1.0 |
| 기준일 | 2026년 11월 14일 |
| 기준 브랜치 | `feat/drive-experience-refinement` |
| 기준 커밋 | `197ed3b` |
| 최신 점수 계산 버전 | `distance-bonus-longitudinal-v2-turn-v2` |
| 문서 용도 | 팀 내부의 이용 규칙 합의와 구현 및 검증 인수인계 |

현재 앱은 참가 내역, 결과, 배지 진행률 및 마일리지 원장을 기기에 저장한다. 실제 사용자들 사이의 온라인 매칭과 순위 확정은 아직 연결하지 않았다. 현재 순위 경쟁과 순위에 따른 경기 마일리지 지급은 시연 참가자를 이용한다. 따라서 이 명세의 시연 정산 규칙을 실제 운영 중인 온라인 대회의 지급 정책으로 설명해서는 안 된다.

## 1 용어와 적용 범위

| 용어 | 의미 |
|---|---|
| 목적지 | 운전자가 실제로 도착하려고 내비게이션에 지정한 장소이다. |
| 개최지 | 앱이 대회를 운영하는 기준 위치이다. 목적지와 개최지는 서로 다른 장소일 수 있다. |
| 회차 | 한국시간을 기준으로 시작 시각과 종료 시각이 정해진 대회 시간대이다. |
| 대회 그룹 | 같은 개최지와 같은 회차에 배정된 참가자들을 구분하기 위한 단위이다. |

| 기록 | 앱이 점수 계산에 사용할 차량 속도 등의 표본을 수집하는 상태이다. |
| 경기 인정 | 앱이 참가권, 도착 시각, 참가 거리 및 데이터 품질 조건을 모두 확인하여 배지와 보상 집계에 사용할 수 있다고 판단한 결과이다. |
| 실격 | 안전벨트 미착용 또는 대회 종료 시각 이후 도착으로 경기 자격을 잃은 결과이다. 앱은 실격을 0점과 구분한다. |
| 확인 불가 | 앱이 이동 중 필수 차량 정보를 확인하지 못하여 정상 경기로 인정할 수 없는 결과이다. 앱은 이를 미착용 위반으로 단정하지 않는다. |

앱의 일반 모드는 실제 차량과 내비게이션에서 수신한 데이터를 사용한다. 시연 모드는 주행 표본과 경쟁자를 이용하여 게임 진행과 화면을 재현한다. 내 기록의 예시 카드와 배지의 달성 예시보기는 저장된 경기나 지갑을 변경하지 않는 화면 예시이다. 이 세 가지 동작을 같은 기능으로 취급하지 않는다.

## 2 참가부터 결과 확인까지의 전체 흐름

1. 운전자가 주차 상태에서 목적지를 선택한다.
2. 앱이 목적지 좌표와 등록된 개최지 좌표를 비교한다. 앱은 목적지에서 반경 1km 이내에 있는 개최지 중 가장 가까운 개최지를 배정한다.
3. 앱이 배정한 개최지, 회차, 마감 시각 및 참가 조건을 보여준다.
4. 앱이 운전석 벨트 착용을 확인하고, 운전자가 참가 조건에 동의하면 챌린지 시작 버튼을 사용할 수 있다.
5. 앱이 내비 경로를 확인한 뒤 참가를 확정한다. 앱은 이 시점에 해당 날짜의 참가권을 사용한 것으로 저장한다.
6. 남은 경로가 10km보다 길면 앱이 예약 상태를 유지한다. 남은 경로가 10km 이하가 되면 앱이 점수 기록을 시작한다.
7. 앱은 차량 속도, 도로 제한속도, 안전벨트, 조향, 방향지시등, GPS 및 내비 회전 안내를 각 판정 규칙에 따라 사용한다.
8. 내비가 도착을 알리면 앱이 기록을 마감한다. 차량이 아직 주차되지 않았다면 앱이 주차를 기다린다.
9. 차량이 주차되면 앱이 결과 인정 여부를 결정하고, 해당 결과에 허용되는 기록·배지·마일리지를 저장한다.
10. 운전자는 완료 알림 또는 내 기록에서 결과를 확인한다. 앱은 결과를 다시 열었다는 이유로 보상을 다시 지급하지 않는다.

앱은 도착을 단순히 남은 거리가 0m가 됐다는 이유만으로 확정하지 않는다. 일반 경기의 도착 판정에는 내비의 도착 이벤트와 해당 경로의 목적지 식별자가 필요하다.

## 3 참가 조건과 하루 한 경기 규칙

### 3.1 참가할 수 있는 차량 상태

일반 모드에서 앱은 차량이 P단이고, 최근 차량 속도가 0.1m/s 미만이며, 차량의 화면 사용 제한이 해제되어 있을 때 주차 상태로 판단한다. 앱은 속도 정보가 2.5초보다 오래되면 그 정보만으로 주차 상태를 인정하지 않는다.

운전자가 챌린지를 시작하려면 앱이 운전석 벨트의 최신 체결값을 확인해야 한다. 운전석 벨트가 미착용이거나, 체결값이 없거나, 체결값이 2.5초보다 오래되면 앱은 시작 버튼을 비활성화한다. 벨트 경고등이 꺼졌다는 사실은 체결 확인을 대신하지 않는다.

앱은 운전석 벨트 착용 확인과 참가 조건 동의를 별도로 확인한다. 운전자가 조건에 동의했더라도 벨트를 착용하지 않았다면 시작할 수 없다. 운전자가 벨트를 착용했더라도 조건에 동의하지 않았다면 시작할 수 없다. 현재 목적지로 참가하는 경로에도 같은 벨트 조건을 적용한다.

운전자가 다른 경기에 참가 중이거나, 내비 경로 응답을 기다리고 있거나, 스팟투어 방문 기록을 진행 중이면 앱은 새 경기를 시작하지 않는다. 일반 모드에서는 선택한 회차가 실제 현재 시각을 포함해야 한다.

‘길 안내만 열기’는 챌린지 참가와 별개의 기능이다. 운전자가 이 기능을 선택하면 앱은 일반 길 안내를 열며, 챌린지 참가권이나 경기 보상을 만들지 않는다.

### 3.2 참가권을 사용하는 시점

앱은 참가가 확정될 때 경기 ID와 한국시간의 참가 날짜를 함께 저장한다. 내비 경로 요청 실패, 응답 시간 초과 또는 벨트 조건 미충족으로 참가가 확정되지 않았다면 앱은 참가권을 사용하지 않는다.

내비 요청과 응답 사이에 벨트 상태가 바뀔 수 있으므로, 앱은 내비 응답을 받은 뒤 참가를 확정하기 직전에도 벨트 착용을 다시 확인한다. 이 재확인에서 참가가 차단되면 앱은 그날의 참가권을 사용하지 않는다.

참가가 확정된 후에는 운전자가 경기를 취소하거나, 목적지를 바꾸거나, 실격되거나, 필수 데이터가 부족해 결과를 인정받지 못하더라도 같은 날 다시 참가할 수 없다. 하루 한 경기 제한은 목적지별 제한이 아니다. 다른 개최지나 다른 회차를 선택해도 같은 날의 참가권은 다시 생기지 않는다.

앱은 참가 날짜를 기기에 저장하므로 앱을 다시 열어도 당일 참가 제한을 유지한다. 다만 현재 구현은 기기 로컬 저장 방식이다. 계정이나 여러 기기 전체에 걸친 참가 제한은 서버에서 별도로 구현해야 한다.

### 3.3 날짜와 주의 기준

앱은 참가 날짜, 배지 일수 및 일일 보상 키에 한국시간인 `Asia/Seoul`을 사용한다. 앱은 한 주를 월요일부터 일요일까지로 계산한다.

앱은 경기를 나중에 저장하더라도 참가를 확정한 날짜에 그 경기를 귀속시킨다. 예를 들어 운전자가 23시 50분에 참가하고 23시 59분에 도착한 뒤 다음 날 00시 02분에 주차했다면, 앱은 대회 마감 전에 도착한 것으로 판단하고 원래 참가 날짜에 결과를 반영한다. 반면 해당 회차가 00시에 끝나는데 운전자가 00시 이후에 도착했다면 시간 초과 실격이다. 날짜 귀속 규칙이 마감 이후 도착을 허용하는 것은 아니다.

## 4 개최지 배정과 같은 게임에 속하는 조건

### 4.1 개최지를 배정하는 거리

앱은 현재 차량 위치가 아니라 **내비 목적지 좌표**를 기준으로 개최지를 배정한다. 앱은 목적지와 각 개최지 사이의 지리적 거리를 계산하고, 반경 1,000m 이내에 있는 개최지 중 가장 가까운 한 곳을 선택한다. 거리가 정확히 1,000m이면 범위에 포함한다. 이 거리는 도로를 따라 이동하는 경로 길이가 아니라 위도·경도를 이용한 지표면 거리이다.

두 개최지와의 계산 거리가 정확히 같으면 앱은 개최지 ID 순서로 한 곳을 선택한다. 목적지 좌표가 없거나 유효하지 않으면 앱은 개최지를 임의로 배정하지 않는다. 반경 1km 안에 개최지가 없으면 앱은 챌린지 참가 대신 일반 길 안내를 제공한다.

앱은 개최지를 배정하더라도 사용자가 선택한 실제 목적지를 개최지 중심으로 바꾸지 않는다. 예를 들어 목적지가 개최지에서 700m 떨어진 매장이라면 앱은 해당 매장까지 길을 안내하면서, 그 목적지를 가까운 개최지의 대회에 배정한다.

### 4.2 같은 게임의 식별 기준

현재 코드에서 대회 식별자는 **개최지 ID와 회차 시작 시각**의 조합이다. 따라서 두 운전자의 실제 목적지 이름이 달라도 두 목적지가 같은 개최지에 배정되고 같은 회차에 참가하면 같은 대회 그룹에 속하도록 식별한다.

다음 조건은 서로 구분한다.

| 비교 상황 | 대회 그룹 판단 |
|---|---|
| 두 목적지가 같은 개최지에 배정되고 회차가 같다. | 두 참가자는 같은 대회 그룹의 식별자를 가진다. |
| 두 목적지가 가까워도 배정된 개최지가 다르다. | 두 참가자는 다른 대회 그룹에 속한다. |
| 개최지가 같아도 회차가 다르다. | 두 참가자는 다른 대회 그룹에 속한다. |
| 출발 위치나 전체 주행거리가 다르다. | 그 차이만으로 대회 그룹이 달라지지는 않는다. |

이 식별 규칙은 구현되어 있지만, 앱은 아직 서버에서 실제 참가자들을 모아 대진을 구성하지 않는다. 실제 참가자 검색, 그룹 분할, 회차 종료 후 순위 확정 및 결과 배포는 후속 구현 범위이다.

### 4.3 회차 시간표

앱은 한국시간을 기준으로 다음 회차를 사용한다. 시작 시각은 회차에 포함하고 종료 시각은 포함하지 않는다.

| 요일 | 회차 | 참가 및 도착 인정 시간 |
|---|---|---|
| 월요일부터 금요일 | 새벽 | 00:00 이상 07:00 미만 |
| 월요일부터 금요일 | 출근 | 07:00 이상 10:00 미만 |
| 월요일부터 금요일 | 주간 | 10:00 이상 17:00 미만 |
| 월요일부터 금요일 | 퇴근 | 17:00 이상 20:00 미만 |
| 월요일부터 금요일 | 야간 | 20:00 이상 다음 날 00:00 미만 |
| 토요일과 일요일 | 주말 새벽 | 00:00 이상 08:00 미만 |
| 토요일과 일요일 | 주말 주간 | 08:00 이상 16:00 미만 |
| 토요일과 일요일 | 주말 야간 | 16:00 이상 다음 날 00:00 미만 |

현재 코드는 토요일과 일요일만 주말로 구분한다. 공휴일 전용 시간표는 구현하지 않았다.

### 4.4 현재 등록된 개최지

현재 앱의 등록 목록에는 현대 모터스튜디오 고양, 단국대학교 죽전캠퍼스, 여의도한강공원, 서울숲, 올림픽공원이 들어 있다. 이 목록은 코드에 등록된 데이터이며, 서버에서 실시간으로 운영 개최지를 내려주는 구조는 아니다. ‘우리 동네 공원’ 예시에는 개최지 좌표가 없으므로 같은 매칭 목록에 포함되지 않는다.

화면에 표시하는 참가 예시 인원이나 인기 스팟 인원은 실제 접속자 수가 아니다. 특히 개최지 전체의 예시 인원과 아래에서 설명하는 최대 5명의 시연 비교 그룹은 서로 다른 값이다.

## 5 내비 연결과 기록 구간

### 5.1 내비 경로를 확인하는 과정

운전자가 지도나 검색 결과에서 참가를 선택하면 앱은 내장 내비에 선택한 목적지의 경로를 요청한다. 앱은 요청 이후에 받은 경로 정보가 요청한 개최지에 매칭되는지, 응답 목적지 좌표가 요청 좌표에서 150m 이내인지, 유효한 경로와 목적지 식별자가 있는지 확인한다. 앱은 요청과 무관한 이전 경로를 새 참가의 경로로 사용하지 않도록 검사한다.

앱이 20초 안에 필요한 경로 응답을 받지 못하면 앱은 대기를 종료하고 다시 시도하도록 안내한다. 기존 내비 목적지로 참가하는 경우에는 앱이 최근 목적지 정보, 남은 거리 및 목적지 식별자를 확인한다. 목적지 정보의 유효기간은 10초이다.

### 5.2 서로 다른 거리 기준

| 거리 기준 | 앱이 사용하는 목적 |
|---|---|
| 목적지와 개최지 사이 1,000m | 앱이 어느 대회에 배정할지 결정한다. |
| 내비 경로 응답과 요청 목적지 사이 150m | 앱이 요청한 경로와 응답 경로가 일치하는지 확인한다. |
| 참가 확정 시 남은 내비 경로 10,000m | 앱이 해당 경기를 순위·보상 집계 대상이 될 수 있는 참가로 구분한다. |
| 주행 중 남은 내비 경로 10,000m | 앱이 예약에서 점수 기록 상태로 전환한다. |
| 기록 시작 후 차량 속도로 계산한 최대 10,000m | 앱이 점수 계산에 포함할 구간을 제한한다. |
| 유효하게 평가한 거리 9,000m 이상 | 앱이 완료 결과를 정상 경기로 인정하기 위한 조건 중 하나이다. |
| 스팟투어 목적지와 해당 스팟 사이 150m | 앱이 방문 목적지가 스팟투어 장소와 맞는지 확인한다. |

참가 시 남은 경로가 10km 이상이면 앱은 예약 상태를 만든다. 이후 남은 경로가 10km 이하로 들어오면 앱이 기록을 시작한다. 참가 시점의 거리가 10km보다 짧으면 현재 코드는 즉시 기록할 수 있지만, 해당 경기는 순위·배지·경기 보상 집계 대상이 아니다. 즉, 현재 구현은 ‘10km 미만이면 참가 화면에서 반드시 차단한다’는 방식과 다르다.

기록이 시작된 뒤에는 남은 거리가 다시 증가해도 같은 경기의 기록을 두 번째로 시작하지 않는다. 점수 계산기는 기록 표본의 차량 속도와 시간 차이를 이용해 주행거리를 계산하며, 계산된 첫 10km까지만 채점한다. 내비의 남은 거리 변화 자체를 가점 거리로 사용하지 않는다.

음성 안내가 켜져 있으면 앱은 예약에서 기록 상태로 전환할 때 마지막 10km의 기록을 시작한다고 안내한다. 운전자가 내장 내비로 이동해 앱이 뒤로 가더라도 앱은 기록 서비스를 통해 경기 진행을 유지하도록 구성되어 있다. 주차 후 결과 알림을 제공하려면 기기의 앱 알림 권한이 허용되어 있어야 한다. 결과 도착 음성은 음성 설정과 앱의 화면 표시 상태 등 실행 조건을 함께 따른다.

## 6 안전점수의 전체 체계

### 6.1 점수 계산식

앱이 확인하는 운전 요소는 급가속, 급감속, 제한속도 준수, 안전벨트 및 방향지시등의 다섯 가지이다. 다만 다섯 요소를 같은 방식으로 가감점하지는 않는다.

**최종 원점수 = 기본 60점 + 제한속도 준수 가점 + 가감속 공통 가점 − 방향지시등 감점**

| 요소 | 점수 또는 결과에 반영하는 방식 |
|---|---|
| 제한속도 준수 | 앱은 제한속도를 준수한 유효 거리 1km마다 2.5점을 더하며, 최대 25점을 더한다. |
| 급가속과 급감속 | 앱은 제한속도를 준수하고 급가감속이 확인되지 않은 평가 가능 거리 1km마다 공통으로 1.5점을 더하며, 최대 15점을 더한다. |
| 방향지시등 | 앱은 판정 가능한 회전의 미사용·늦은 사용·반대 방향 사용에 대해 감점하며, 경기 전체에서 최대 10점을 뺀다. |
| 안전벨트 | 앱은 참가 자격과 경기 유효성을 판단한다. 미착용 실격은 단순한 몇 점 감점이 아니다. |

급가속 점수와 급감속 점수는 별도의 두 가점이 아니다. 두 항목은 하나의 가감속 공통 가점을 공유한다. 앱은 급가속이나 급감속 한 건마다 일정 점수를 추가로 빼지 않고, 그 행동이 확인된 구간의 공통 가점을 제외한다.

앱은 최종 원점수를 0점부터 100점 사이로 제한하고 정수로 반올림한다. 다만 실제 원점수가 100점에 도달하지 않았다면 반올림만으로 100점을 표시하지 않으며, 표시 점수를 최대 99점으로 제한한다. 실제 구현에는 부동소수점 계산 오차를 위한 극소 허용값이 있다.

### 6.2 제한속도 준수

앱은 내비가 제공하는 현재 도로의 제한속도와 차량 속도를 비교한다. 차량 속도가 제한속도와 같으면 앱은 제한속도를 준수한 것으로 판단한다. 차량 속도가 제한속도를 넘으면 앱은 해당 초과 거리의 속도 가점을 지급하지 않는다.

앱은 같은 과속 구간에 가감속 공통 가점도 지급하지 않는다. 따라서 과속 구간에서 급가감속까지 발생하더라도 이미 제외한 공통 가점을 두 번 제외하지 않는다.

앱은 제한속도가 바뀌거나 속도가 기준을 넘나드는 표본 사이에서 선형으로 속도를 추정하여 준수 거리와 초과 거리를 나눈다. 앱은 임의의 ‘제한속도보다 몇 km/h까지 허용’ 오차를 추가하지 않는다. 현재 코드가 받아들이는 제한속도 범위는 1km/h부터 150km/h까지이며, 제한속도 데이터의 유효기간은 5초이다. 제한속도를 모르거나 유효기간이 지났다면 앱은 해당 구간을 정상 준수로 간주하지 않는다.

### 6.3 급가속

앱은 차량 속도 표본 사이의 속도 차이를 시간 차이로 나누어 가속도를 계산한다. 앱은 최근 세 구간의 가속도 중앙값으로 순간적인 튐을 줄인다. 초기 두 구간에는 유효한 원래 계산값을 사용한다.

앱은 가속도가 +2.5m/s² 이상인 상태가 1초 이상 지속되고, 이를 뒷받침하는 유효 구간이 최소 세 개 이상이면 급가속으로 확정한다. 앱은 확정된 급가속 구간에 해당하는 거리의 가감속 공통 가점을 제외한다.

### 6.4 급감속

앱은 원래 차량 속도 표본을 이용해 최근 정확히 1초 동안의 평균 가속도를 계산한다. 이 값이 −3.0m/s² 이하이면 앱은 급감속 조건을 충족한 것으로 판단한다. 앱은 이 조건을 만족한 뒤 별도의 1초를 추가로 기다리지 않는다.

앱은 해당 1초 구간 중 실제 속도가 줄어든 부분의 공통 가점을 제외한다. 같은 구간 안에서 속도가 유지되거나 증가한 부분까지 급감속이라는 이유만으로 모두 제외하지 않는다.

브레이크를 밟았다는 사실만으로 급감속이 되는 것은 아니다. 앱은 브레이크 상태를 급감속 기록의 참고 정보로 보관하며, 브레이크 신호 자체에 별도의 감점을 부여하지 않는다.

### 6.5 사건 횟수와 가점 제외 거리

앱은 같은 종류의 급가감속 사건이 같은 유효 데이터 구간에서 2초 이내의 간격으로 이어지면 표시 사건을 묶을 수 있다. 앱은 사건을 묶더라도 사건 사이의 정상 구간까지 모두 가점에서 제외하지 않는다. 앱은 실제로 기준을 충족한 구간의 합집합에 대해서만 가점을 제외한다.

따라서 ‘급가속 1회’라는 횟수만으로 손실 점수를 고정할 수 없다. 같은 한 번의 급가속이라도 앱이 확인한 지속시간과 주행거리에 따라 받지 못한 가점이 달라진다.

### 6.6 계산 사례

다음 사례는 데이터 품질과 참가 조건이 충족된 10km 경기이며, 따로 언급하지 않은 방향지시등 감점은 없다고 가정한다.

| 사례 | 계산과 표시 결과 |
|---|---|
| 운전자가 10km 전체에서 제한속도를 지키고 급가감속 없이 주행했다. | 앱은 60 + 25 + 15 = 100점을 표시한다. |
| 운전자가 1km에서 과속했고, 나머지 9km에서는 제한속도를 지키며 부드럽게 주행했다. | 앱은 60 + 22.5 + 13.5 = 96점을 표시한다. |
| 운전자가 제한속도를 모두 지켰지만 급가감속으로 확정된 거리의 합이 0.5km였다. | 앱은 60 + 25 + 14.25 = 99.25점을 계산하고 99점을 표시한다. |
| 바로 위 경기에서 앱이 방향지시등 미사용 회전 한 건을 추가로 확정했다. | 앱은 99.25 − 1 = 98.25점을 계산하고 98점을 표시한다. |
| 운전자가 위 조건에서 높은 점수를 얻었더라도 이동 중 벨트 미착용으로 실격됐다. | 앱은 정상 점수를 확정하지 않고 실격 사유를 표시한다. |

## 7 방향지시등 판정

### 7.1 회전을 판단하는 근거

앱은 핸들을 돌렸다는 사실 하나만으로 방향지시등 위반을 판단하지 않는다. 앱은 내비의 좌회전·우회전 안내, GPS 진행방향 변화, 조향 방향, 차량의 전진 상태, 속도, 방향지시등 및 비상등 상태를 함께 확인한다.

앱이 회전 후보를 시작하려면 내비가 안내한 방향과 조향 방향이 일치해야 한다. 회전 지점까지의 안내 거리는 0m 이상 40m 이하이고, 회전 안내 정보는 10초 이내의 값이어야 한다. 차량은 전진 중이어야 하며, 속도는 2m/s 이상 25m/s 이하이어야 한다.

앱은 최근 중립 조향을 확인한 뒤 좌측 −5도 이하 또는 우측 +5도 이상의 정규화된 조향을 회전 후보로 본다. 앱은 Pleos에서 받은 원래 조향 부호를 판정 기준에 맞춰 변환한다. 이 값은 현재 SDK의 조향 신호이며, 별도의 앞바퀴 실측 센서를 추가로 확인했다는 의미가 아니다.

앱은 회전 후 조향이 절댓값 2도 이내로 1초 이상 돌아왔을 때 결과를 평가한다. 앱은 같은 방향의 조향이 최소 500ms 이상 확인됐는지, GPS 진행방향이 그 방향으로 35도 이상 135도 이하 바뀌었는지, 전후 위치가 15m 이상 이동했는지 등을 확인한다. 앱은 위치 점프, 반대 방향의 큰 조향 또는 불충분한 GPS 표본이 있으면 판정을 보류한다.

### 7.2 방향지시등 사용과 감점

| 앱이 확인한 행동 | 처리 |
|---|---|
| 운전자가 회전 전에 올바른 방향지시등을 충분히 유지했다. | 앱은 정상 일치로 기록하고 감점하지 않는다. |
| 운전자가 판정 가능한 회전에서 방향지시등을 사용하지 않았다. | 앱은 1점을 뺀다. |
| 운전자가 필요한 사전 사용을 충족하지 못하고 회전 시작 후에 올바른 방향지시등을 켰다. | 앱은 늦은 사용으로 1점을 뺀다. |
| 운전자가 회전 전에 반대 방향지시등을 지속해서 사용했다. | 앱은 반대 방향 사용으로 2점을 뺀다. |
| 앱이 신호 이력이나 위치 자료를 충분히 받지 못했다. | 앱은 판단 보류로 기록하고 감점하지 않는다. |
| 비상등이 켜졌거나 비상등 상태를 확인하지 못했다. | 앱은 해당 회전의 방향지시등 판정을 보류한다. |

정상 사전 사용을 확인하려면 앱은 회전 시작 전에 서로 다른 관측값에서 같은 방향지시등이 최소 500ms 동안 이어졌는지 확인한다. 앱은 마지막으로 그 조건이 충족된 시점이 회전 시작 전 1초 이내인지도 확인한다. 신호 표본의 유효기간과 연속성 허용 간격은 750ms이다. 동일한 캐시 값을 반복해서 읽은 것은 새로운 500ms의 사용 증거가 되지 않는다.

앱은 짧게 들어온 반대 신호 한 번만으로 2점을 빼지 않는다. 반대로 앱이 지속된 반대 방향 사용을 이미 확인했다면 운전자가 회전 후 올바른 신호로 바꿨다는 이유로 그 판정을 없애지 않는다.

앱은 한 경기의 방향지시등 감점을 최대 10점까지만 반영한다. 위 수치는 앱의 프로토타입 판정 기준이며, 법규의 방향지시등 의무 거리나 시간을 그대로 구현한 기준은 아니다.

### 7.3 GPS 품질과 차선변경

회전 판정에 사용하는 GPS는 최근 1.5초 이내의 값이어야 한다. 앱은 위치 정확도가 10m 이내이고 진행방향 정확도가 15도 이내인 표본을 사용하며, 회전 후보에는 서로 다른 GPS 시각의 표본을 최소 세 개 요구한다. 회전 후보는 최대 20초 동안 관측하고, 완료 뒤에는 3초의 재판정 대기시간을 둔다.

차선변경은 현재 감점 대상이 아니다. 앱은 좌우로 이어지는 조향, 진행방향 복귀 및 정밀한 GPS 횡이동을 이용해 차선변경 후보를 관찰한다. 앱은 이 후보를 실제 차선 경계를 넘은 사건으로 확정하지 않으며, 후보의 감점은 항상 0점이다. 내비 회전 문맥과 GPS가 부족할 때 핸들 각도만으로 일반 굽은 도로를 위반 처리하지 않는다.

## 8 안전벨트와 경기 자격

### 8.1 참가 전과 참가 후의 차이

참가 전에는 정차 중이어도 운전석 벨트 미착용·미확인 상태가 참가를 막는다. 참가가 확정된 뒤에는 정차 중 벨트를 풀었다는 이유만으로 실격하지 않는다.

앱은 참가 이후 D 또는 R 상태에서 속도의 절댓값이 0.1m/s를 초과할 때 이동 중으로 판단하고 벨트 실격을 검사한다. 이 기준은 약 0.36km/h이다. 앱은 전진과 후진을 모두 검사한다. 예약 상태에서 아직 10km 기록 구간에 진입하지 않았더라도 벨트 실격 검사는 적용된다.

### 8.2 운전석과 조수석

앱은 이동 중 운전석 벨트를 항상 검사한다. 앱은 조수석에 사람이 앉아 있다고 확인한 경우 조수석 벨트도 검사한다. 조수석이 비어 있다고 확인한 경우에는 조수석 벨트 미착용만으로 실격하지 않는다. 현재 경기 자격 판정에는 뒷좌석 벨트를 포함하지 않는다.

앱은 이동 중 조수석 탑승 신호가 갑자기 사라졌다는 이유로 조수석이 비었다고 간주하지 않는다. 한 번 탑승을 확인한 조수석의 검사 의무를 해제하려면 앱은 정차 중에 빈 좌석 상태가 서로 다른 새 관측값으로 2초 이상 확인되어야 한다.

### 8.3 미착용 확정과 데이터 부족

앱은 이동 중 미착용을 한 번 읽었다고 곧바로 실격시키지 않는다. 앱은 서로 다른 최신 체결 관측값에서 미착용이 500ms 이상 확인되면 실격을 확정한다. 현재 좌석 조회 간격의 영향으로 실제 확정은 이론상의 500ms보다 늦을 수 있다.

앱은 필요한 좌석·속도·기어 정보를 확인하지 못하면 미착용으로 단정하지 않는다. 대신 앱은 이동 중 확인 불가 이력을 남기고 해당 경기의 정상 점수·배지·마일리지 집계를 제외한다. 이후 통신이 회복되어도 이미 확인하지 못한 이동 구간이 사라지지는 않는다.

벨트 판정에서 속도 표본의 유효기간은 500ms이고, 기어·좌석 관련 표본의 유효기간은 2.5초이다. 앱은 오래된 값, 역순으로 들어온 값 및 확인되지 않은 상태를 정상 착용으로 채우지 않는다.

### 8.4 실격의 저장

앱은 벨트 실격이 확정되면 실격 사유와 경기 기록을 즉시 저장한다. 운전자가 이후 벨트를 다시 매거나 앱을 다시 열어도 앱은 이미 확정한 실격을 취소하지 않는다. 앱은 운전석과 조수석이 동시에 실격 조건을 충족하면 운전석 사유를 우선 표시한다.

| 상황 | 앱의 동작 |
|---|---|
| 참가 전 운전석 벨트가 미착용 또는 미확인이다. | 앱은 참가 버튼을 비활성화하고 참가권을 사용하지 않는다. |
| 참가 후 차량이 정차했고 운전자가 벨트를 풀었다. | 앱은 그 이유만으로 실격시키지 않는다. |
| 참가 후 차량이 D 또는 R로 이동하고 운전석 미착용이 확정됐다. | 앱은 운전석 안전벨트 미착용으로 실격 처리한다. |
| 차량이 이동하고, 조수석 탑승과 조수석 미착용이 확정됐다. | 앱은 조수석 안전벨트 미착용으로 실격 처리한다. |
| 차량이 이동하고 조수석이 비어 있다고 확인됐다. | 앱은 조수석 벨트 미착용만으로 실격시키지 않는다. |
| 차량이 이동하는 동안 필수 차량 정보가 누락됐다. | 앱은 확인 불가 이력을 남기며 정상 경기 집계에서 제외한다. |

## 9 데이터 품질과 결과 인정

### 9.1 숫자 점수와 경기 인정은 다르다

앱이 숫자 점수를 계산할 수 있다는 사실만으로 그 경기가 배지나 보상 집계 대상이 되는 것은 아니다. 점수 계산기는 유효 거리 500m 이상, 제한속도·속도 관련 시간 기준 수신율 90% 이상 및 가감속 평가 준비 조건을 만족하면 개인 분석용 숫자 점수를 만들 수 있다.

정상 경기로 인정하려면 아래 조건을 모두 충족해야 한다.

1. 앱이 해당 참가 날짜에 경기 참가권을 정상적으로 확보했어야 한다.
2. 참가 확정 시 남은 내비 경로가 10km 이상이어야 한다.
3. 운전자가 해당 회차의 시작 시각 이상, 종료 시각 미만에 도착해야 한다.
4. 앱이 점수 계산 구간에서 최소 9km의 유효 거리를 확보해야 한다.
5. 앱의 속도·제한속도 관련 시간 기준 수신율이 90% 이상이어야 한다.
6. 가감속 평가에 사용할 수 있는 구간의 시간 비율이 90% 이상이고, 유효 표본 간격으로 계산한 수신 빈도가 초당 8회 이상이어야 한다.
7. 앱이 안전벨트 실격 또는 이동 중 필수 정보 확인 불가 이력을 갖고 있지 않아야 한다.
8. 점수 계산기가 최종 숫자 점수를 확정할 수 있어야 한다.

앱은 속도 표본 사이가 300ms보다 벌어지면 해당 구간을 연속적인 급가감속 판단에 사용하지 않는다. 앱은 일반 거리 계산에서도 2.5초를 넘는 간격, 누락 속도 및 비정상 표본을 유효하게 채점하지 않는다. 앱은 누락 데이터를 임의의 정상 주행으로 보충하지 않는다.

여기서 수신율 90%는 단순히 ‘표본 열 개 중 아홉 개’라는 뜻이 아니다. 현재 구현은 표본의 시각 차이로 누적한 전체 평가 시간과 유효 시간을 비교한다. 가감속의 수신 빈도 조건은 별도로 검사한다.

방향지시등 판정 자료가 없는 것만으로 경기 전체가 자동으로 실격되지는 않는다. 앱은 해당 회전의 감점을 보류하고 자료 부족을 설명한다. 이 동작은 안전벨트 필수 정보의 확인 불가 처리와 다르다.

### 9.2 대회 마감과 주차

앱은 주차 시각이나 결과 저장 시각이 아니라 **내비가 알린 도착 시각**을 마감 판단에 사용한다. 종료 시각과 정확히 같은 시각에 도착한 경우도 시간 초과 실격이다.

예를 들어 17시에 끝나는 회차에서 운전자가 16시 59분 50초에 도착하고 17시 01분에 주차했다면 앱은 마감 전 도착으로 판단한다. 운전자가 17시 00분 00초에 도착했다면 앱은 시간 초과 실격으로 판단한다. 두 경우 모두 다른 참가 및 데이터 품질 조건은 별도로 검사한다.

현재 구현은 회차 종료 순간에 자동 타이머로 모든 경기를 즉시 실격시키는 방식이 아니다. 앱은 도착 후 결과를 확정할 때 도착 시각을 회차 마감과 비교한다.

## 10 순위와 경기 마일리지

### 10.1 현재 구현 범위

일반 모드에서 앱은 인정된 개인 경기와 일반 배지 진행률을 저장할 수 있지만, 실제 다른 사용자의 결과를 받아 순위를 확정하지 않는다. 일반 모드의 경기 순위 마일리지는 현재 지급하지 않는다.

시연 모드에서는 앱이 예시 경쟁자의 점수와 사용자 점수를 비교한다. 정산 함수는 최대 5명의 유효 참가자를 지원하며, 참가자 ID가 중복되면 한 번만 포함한다. 앱은 유효 참가자를 점수 내림차순으로 정렬한다.

### 10.2 참가자 수에 따른 지급 슬롯

다음 표는 현재 시연 정산 함수에 구현된 지급량이다. 각 참가자의 점수가 85점 이상이어야 해당 참가자가 배정된 슬롯의 마일리지를 받을 수 있다.

| 유효 참가자 수 | 1위 슬롯 | 2위 슬롯 | 3위 슬롯 | 4위 슬롯 | 5위 슬롯 |
|---|---:|---:|---:|---:|---:|
| 1명 또는 2명 | 0M | 0M | 해당 없음 | 해당 없음 | 해당 없음 |
| 3명 | 60M | 20M | 0M | 해당 없음 | 해당 없음 |
| 4명 | 80M | 40M | 20M | 0M | 해당 없음 |
| 5명 | 100M | 60M | 30M | 0M | 0M |

5명 그룹에서 사용자가 단독 1위를 기록하고 85점 이상을 받으면 앱은 경기 마일리지 100M를 배정한다. 사용자가 84점으로 1위를 기록했더라도 앱은 경기 마일리지를 지급하지 않는다. 보상을 받지 못한 슬롯을 다른 참가자에게 재분배하는 로직은 없다.

### 10.3 동점 처리

앱은 같은 점수를 받은 참가자에게 같은 등수를 부여한다. 예를 들어 두 명이 공동 1위이면 다음 참가자는 3위이다. 앱은 동점자들이 차지하는 지급 슬롯의 합계를 동점자 수로 나눈 정수 마일리지를 각자에게 지급한다.

5명 그룹에서 두 명이 공동 1위라면 앱은 1위 100M와 2위 60M를 합쳐 각자 80M를 배정한다. 세 명이 공동 1위라면 앱은 190M를 세 명으로 나눈 정수값인 63M를 각자 배정한다. 현재 구현은 나눗셈의 나머지를 추가 배분하지 않는다. 동점자에게도 85점 이상이라는 지급 기준을 적용한다.

### 10.4 중복 지급 방지

앱은 경기 ID를 기준으로 같은 경기의 마일리지를 한 번만 지급한다. 앱은 참가 날짜를 기준으로도 경기 마일리지를 중복 지급하지 않는다. 완료 이벤트를 다시 받거나 사용자가 결과를 다시 열어도 최초 지급 기록을 유지한다.

## 11 배지와 배지 마일리지

### 11.1 공통 원칙

앱은 경기로 획득하는 배지에 대해 ‘경기 인정’ 결과만 진행률에 반영한다. 실격, 확인 불가 및 참가 거리·유효 데이터 부족 결과는 획득 일수에 포함하지 않는다. 앱은 같은 날짜에 점수를 여러 번 추가하거나 더 높은 점수로 교체하지 않는다.

배지 컬렉션은 매월 초기화되는 구조가 아니다. 앱은 인정된 날짜와 방문 날짜를 누적하여 보관한다. ‘네 주의 동행’은 한 달 안의 네 주나 연속된 네 주를 요구하지 않으며, 서로 다른 네 주의 참여를 요구한다.

앱은 진행률이 획득 기준을 처음 넘어설 때 배지 보상을 지급한다. 앱은 배지 ID별 원장에 지급 사실을 남기므로 같은 배지를 다시 조회해도 보상을 다시 지급하지 않는다. 같은 경기에서 여러 배지 조건을 처음 충족하면 앱은 해당 배지들의 마일리지를 함께 더한다.

‘당신도 이제 무사즈!’ 환영 배지는 기본으로 제공하며 보상은 0M이다. 배지의 달성 예시보기는 컬렉션 화면을 바꾸는 기능이며, 예시를 열었다는 이유로 앱이 지갑에 마일리지를 넣지는 않는다.

위 합계에는 이전 배지 화면에 남아 있는 ‘첫 무사 도착’, 목적지별 ‘첫 발자국’, ‘무사 TOP 3’ 배지를 포함하지 않는다. 현재 이 이전 배지들의 개별 마일리지 값은 0M이다.

사용자는 주차 상태에서 스팟투어 방문 기록을 먼저 시작해야 한다. 앱은 해당 스팟과 일치하는 내비 목적지를 확인하고, 방문 기록을 시작한 뒤의 동일 경로 도착과 주차를 확인해야 방문을 인정한다. 사용자가 스팟 이름을 검색하거나 화면을 열었다는 사실만으로는 방문 횟수가 증가하지 않는다.

앱은 장소별로 한국시간 하루 한 번만 방문을 인정하고, 배지에 필요한 서로 다른 세 날짜까지 저장한다. 앱은 경로를 확인한 뒤 길 안내가 취소되거나 방문 기록이 4시간을 넘으면 기록을 종료한다. 챌린지 경기와 스팟투어 방문 기록은 동시에 진행하지 않는다.

스팟투어는 경기의 하루 참가권과 별도로 집계한다. 앱은 스팟투어에 경기 점수 85점, 남은 거리 10km 또는 순위 조건을 요구하지 않는다. 해당 스팟의 세 번째 인정 방문에서 배지와 50M를 지급한다.

## 13 마일리지와 쿠폰

앱은 경기 순위 마일리지와 배지 획득 마일리지를 구분하여 저장하고, 지갑 잔액에는 두 지급량을 더한다. 예를 들어 사용자가 시연 경기 단독 1위로 100M를 받고 같은 경기에서 ‘첫 발걸음’ 배지를 처음 획득하면 앱은 총 115M를 더한다. 다른 배지도 함께 획득했다면 그 보상도 추가한다.

앱은 일반 모드와 시연 모드의 잔액, 지급 이력, 배지 진행률 및 교환 이력을 별도로 저장한다. 사용자가 시연으로 마일리지를 모아도 일반 모드의 잔액이 증가하지 않는다.

현재 교환 기능은 시연 모드에서만 작동한다. 사용자는 주차 상태이고 잔액이 충분해야 교환할 수 있으며, 현재 구현에서는 같은 종류의 상품을 다시 교환할 수 없다.

| 교환 상품 | 필요한 마일리지 |
|---|---:|
| 와이퍼 교환 | 80M |
| 에어컨 필터 교환 | 300M |
| 엔진오일 교환 | 600M |

앱은 교환할 때 필요한 마일리지를 차감하고 교환 이력과 번호를 저장한다. 교환권 번호는 `AJ-XXXX-XXXX-XXXX` 형식이며, 뒤의 열두 자리는 UUID에서 가져온 16진수 문자이다. 앱은 재조회할 때 같은 저장 번호를 보여준다. 이 번호는 현재 앱에서 생성한 시연 식별자이며, 외부 정비소나 쿠폰 발행사의 실사용 인증번호가 아니다.

시연 쿠폰함에 기본으로 보여주는 예시 쿠폰은 실제 지갑에서 마일리지를 차감해 발급한 이력과 구분한다. 일반 모드의 실쿠폰 발행, 사용 처리, 취소·환불, 재발급 및 외부 번호 검증은 아직 연결하지 않았다.

## 14 내 기록과 운전 습관 설명

### 14.1 저장하는 결과

앱은 경기 ID, 실제 목적지, 개최지와 대회 그룹 ID, 참가일, 결과 저장 시각, 점수 계산 버전, 주행거리, 수신 품질, 급가감속과 회전 판정, 경기 인정 여부, 실격 사유, 순위 및 지급 내역을 결과에 저장한다. 앱은 새 계산 규칙이 생겼다고 과거 기록의 점수나 지급량을 임의로 다시 계산하지 않는다.

주간·월간 달력은 참가일을 기준으로 경기를 묶는다. 목록 행의 주행일 표시는 현재 `completedAtEpochMs`에 저장한 결과 완료 시각을 사용한다. 그러므로 자정 근처의 경기에서는 달력에 속한 날짜와 목록 행에 표시된 완료 날짜가 다를 수 있다. 내비 도착 시각은 마감 판단에 사용하지만 현재 완료 기록의 독립 필드로 그대로 보관하지는 않는다.

앱은 실격을 0점으로 표시하지 않는다. 숫자 0점은 점수를 계산한 결과이고, 실격은 경기 자격을 잃은 결과이기 때문이다. 앱은 확인 불가와 데이터 부족도 정상 점수와 구분하여 설명한다.

### 14.2 이어갈 습관과 개선할 점

앱은 저장된 결과의 수치를 정해진 문장 템플릿에 넣어서 설명을 만든다. 앱은 생성형 AI에 운전 평가 문장을 요청하지 않으며, 저장되지 않은 행동을 추측하여 문장을 만들지 않는다.

예를 들어 앱이 유효 거리 10,000m와 과속 거리 1,133m를 저장했다면, 앱은 제한속도 준수 거리를 8,867m로 계산하여 ‘제한속도를 지킨 구간이 8,867 m 있었어요.’라는 문장을 만든다. 앱은 같은 결과에서 ‘제한속도를 초과한 거리가 1,133 m예요. 제한속도 표지를 확인하며 주행해 주세요.’라는 개선 문장도 만든다.

| 저장된 근거 | 앱이 만드는 설명 |
|---|---|
| 급가속 횟수가 2회이다. | 앱은 ‘급가속 2회가 기록됐어요. 가속 페달을 천천히 밟아 보세요.’라고 안내한다. |
| 급감속 횟수가 1회이다. | 앱은 ‘급감속 1건이 확인됐어요. 앞차와 거리를 충분히 두고 도로 상황을 미리 살펴보세요.’라고 안내한다. |
| 정상 사전 신호가 확인된 회전이 있다. | 앱은 확인된 회전 횟수를 넣어 방향지시등을 미리 맞게 켰다고 설명한다. |
| 늦은 신호 또는 반대 방향 신호가 있다. | 앱은 해당 종류의 확인 횟수를 넣어 개선할 행동을 안내한다. |
| 회전 판정 자료가 없다. | 앱은 방향지시등 사용 여부를 평가하지 않았다고 안내한다. |
| 점수나 필수 분석 자료가 부족하다. | 앱은 운전이 안전했다고 단정하지 않고 판단에 필요한 기록이 부족하다고 안내한다. |

운전 습관 요약의 과속·급가속·급감속·방향지시등 카드에는 거리 또는 횟수를 보여준다. 앱은 급가속과 급감속 카드에 독립된 가점처럼 보이는 수치를 각각 표시하지 않는다. 별도의 점수 상세와 설명 문장은 저장된 공통 가점과 감점 내역을 사용할 수 있다.

## 16 구현 상태와 추가 확인 사항

### 16.1 코드와 검증의 범위

현재 브랜치에는 점수 계산, 벨트 자격 판정, 하루 참가 제한, 결과 인정, 일반 배지와 배지 마일리지, 시연 순위 정산, 저장 결과의 문장 생성 및 쿠폰 시연이 구현되어 있다. 기준 커밋의 병합 검증에서는 단위 테스트 214개와 에뮬레이터의 서로 다른 34개 시나리오를 통과했다.

이 통과 수치는 실제 도로와 모든 SDK 입력을 종단 검증했다는 의미는 아니다. 벨트 체결 조합의 일부 검사는 앱에 관측값을 넣는 방식으로 수행했다. 실제 콘솔에서는 조수석 탑승 여부와 경고등을 바꿀 수 있었지만, 운전석과 조수석의 체결 원시값을 각각 착용으로 바꾸는 경로를 확보하지 못했다.

방향지시등 검증은 실제 콘솔의 속도·기어·조향·신호·비상등과 모의 GPS·모의 내비 안내를 결합하여 수행했다. 가상 GPS를 실제 내장 내비까지 연결하는 추가 검사에서는 Android 위치와 내비 위치가 일치하지 않았고 NMEA 체크섬 오류가 확인됐다. 따라서 실제 GPS 경로와 내비 회전 안내를 모두 연결한 주행 검증은 아직 완료되지 않았다.

### 16.2 운영 전에 필요한 후속 구현

| 항목 | 필요한 작업과 이유 |
|---|---|
| 실제 참가자 매칭 | 서버가 계정, 개최지, 회차 및 참가 상태를 관리하고 같은 대회의 참가자 목록을 구성해야 한다. 현재 앱에는 대회 식별 규칙과 시연 그룹만 있다. |
| 그룹 규모와 순위 확정 | 팀은 대회 전체 순위와 소규모 비교 그룹을 구분하고, 회차 종료 전 결과를 임시 순위로 보여줄지 결정해야 한다. 최대 5명의 시연 정산 함수를 그대로 전체 대회 정산으로 사용할 수는 없다. |
| 실제 랭킹 배지 | 서버의 확정 순위와 참가자 수를 앱의 랭킹 배지 진행률에 연결해야 한다. 일반 모드 계산 함수의 최소 10명 조건도 운영 매칭 정책과 맞춰야 한다. |
| 계정 단위 하루 참가 제한 | 서버가 참가권을 원자적으로 확보하고 기기 변경·재설치·동시 요청에서도 한 번만 사용되도록 보장해야 한다. |
| 참가와 기록 복구 | 앱은 확정 참가일을 유지하지만, 진행 중 예약을 앱 프로세스 종료 뒤 어디까지 복구하고 취소 이력을 어떻게 보여줄지 추가로 정의해야 한다. |
| 실쿠폰과 광고 운영 | 외부 발행 번호, 실제 사용 확인, 재발급·환불 정책과 광고 스팟 등록·계약·정산 기능을 연결해야 한다. 현재는 코드에 등록된 상품과 장소를 사용한다. |
| 좌석별 벨트 검증 | 팀은 운전석 착용과 조수석 탑승·체결을 독립적으로 조작할 수 있는 환경에서 SDK부터 실격 저장까지 확인해야 한다. |
| 실제 GPS와 내비 회전 검증 | 팀은 내장 내비가 가상 이동을 실제로 수신하는 환경을 확보하고 동일한 좌우회전 경로에서 신호 켬·끔을 비교해야 한다. |
| 차선변경 | 팀은 도로·차로 정보 또는 추가 센서 없이 후보를 실제 위반으로 확정하지 않아야 한다. 현재 관찰 전용과 감점 0점을 유지한다. |
| 도착 시각의 감사 추적 | 팀이 경기 마감 분쟁을 확인하려면 결과 완료 시각과 별개로 내비 도착 시각 및 적용한 회차 정보를 결과에 보관하는 방안을 검토해야 한다. |

### 16.3 이번 정리에서 확인한 불일치

‘현대 모터스튜디오 고양’은 챌린지 개최지 코드에 `(37.6661, 126.8224)`로 등록되어 있고, 스팟투어 코드에는 `(37.66626, 126.74770)`으로 등록되어 있다. 두 좌표는 서로 다르다. 현재 명세는 어느 좌표가 실제 시설의 정확한 좌표라고 확정하지 않는다. 팀은 실제 장소 정보를 확인한 뒤 두 기능이 의도한 위치를 사용하는지 정리해야 한다. 이 불일치는 대회 배정과 방문 인정에 영향을 줄 수 있다.

내 기록의 달력 귀속은 참가일을 사용하지만 목록 행은 결과 완료 시각을 ‘주행일’로 표시한다. 이 차이는 구현상 존재하므로, 팀은 표시 문구를 ‘완료 시각’으로 명확히 할지 검토할 수 있다.

현재 10km 미만 경기는 기록을 시작할 수 있지만 보상 집계에서 제외된다. 팀이 참가 버튼 단계부터 이런 경기를 막고 싶다면 별도의 정책 변경과 구현이 필요하다. 이 명세는 해당 동작을 임의로 변경하지 않았다.
