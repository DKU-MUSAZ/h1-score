# 안전벨트 실격 판정 구현·검증

대상: `feat/drive-experience-refinement`, Pleos Connect 2.1.0 / Vehicle SDK 2.3.2. 급가속·급감속·제한속도 채점식은 변경하지 않았다.

## 적용 기준

- 참가 전에는 정차 중이라도 운전석 벨트의 최신 체결값이 확인돼야 한다. 미착용·미확인·2.5초를 넘긴 값은 참가를 차단하며, 경고등이 꺼졌다는 이유만으로 착용으로 인정하지 않는다.
- 챌린지 시작 버튼은 **운전석 벨트 착용 확인 + 참가 조건 동의**를 모두 만족해야 활성화된다. 현재 목적지로 참가하는 경로에도 같은 벨트 조건을 적용한다. 내비 응답 후 예약을 확정할 때 다시 검사하며, 차단된 시도는 하루 참여를 소모하지 않는다. 시연 모드는 실제 벨트 신호 조건을 적용하지 않는다.
- D 또는 R이며 속도의 절댓값이 0.1 m/s를 초과할 때만 벨트 실격을 판단한다. P/N 또는 정차 중 벨트를 풀었다는 이유로 실격시키지 않는다.
- 운전석은 항상 검사하고, 조수석은 탑승이 확인됐을 때 검사한다. 뒷좌석은 이번 범위에서 제외한다.
- 미착용이 서로 다른 최신 관측값으로 500ms 이상 확인돼야 실격한다. 현재 좌석 조회 주기는 1초이므로 실제 확정 시점은 수신 주기의 영향을 받는다. 캐시를 반복 읽는 것만으로 확정하지 않는다.
- 이동 중 조수석 탑승 신호가 사라져도 빈 좌석으로 간주하지 않는다. 정차 중 빈 좌석이 2초 이상 새 관측값으로 확인되면 조수석 검사 의무를 해제한다.
- 속도·기어·필요한 좌석 신호의 누락/지연/연결 단절은 미착용으로 단정하지 않는다. 이동 중 확인하지 못한 구간은 기록에 남겨 해당 경기의 점수·순위·마일리지·배지 적립을 제외한다.
- 실격은 즉시 저장한다. 다시 벨트를 매거나 결과를 재조회해도 취소되지 않는다.

## 내 기록

목록·월간 달력·상세에 숫자 0점 대신 `실격` 또는 `확인 불가`를 표시한다. 상세에 운전석/조수석 미착용 또는 데이터 확인 불가 사유를 표시하며, 실격 기록에 정상 점수·순위·적립 보상을 노출하지 않는다. 기존 저장 기록은 종전 점수를 그대로 읽는다.

## SDK 연결에서 발견하고 보완한 내용

Vehicle 2.3.2의 좌석 Boolean 변환에 의존하면 콘솔 탑승 상태를 잘못 해석했다. 같은 SDK가 사용하는 좌석 조회 서비스에서 원시값을 읽고, 미확인 상태를 보존하도록 했다. 추가 권한 부여나 에뮬레이터 시스템 수정은 하지 않았다.

| 데이터 | 실제 관찰 / 처리 |
|---|---|
| 조수석 탑승 | 콘솔 Empty → 원시값 1 → 비탑승, Occupied → 2 → 탑승 |
| 탑승 미확인 | 0, 누락, 형식 오류 → 미확인 |
| 벨트 체결 | 에뮬레이터 미착용 원시값 `false` 확인. `true/false`, `1/0`을 구분하고 나머지는 미확인 |
| 연결 단절 | 즉시 운전석·조수석 체결 및 탑승 관측을 무효화. 빠른 복구가 단절 사실을 덮어쓰지 않도록 관측 큐 유지 |

`vehicle-aidl:1.1.1`, `vehicle-data:1.1.11`은 Vehicle 2.3.2에 이미 포함되는 실행 의존성과 같은 버전을 컴파일에 노출한다. SDK 업그레이드 시 원시값 계약을 재확인해야 한다.

## 실제 콘솔 → SDK → 판정 검증

[공식 콘솔 가이드](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/use-vehicle-emulator)에 따라 8088 포트를 연결했다. 브라우저 화면 자동화는 URL 확인 실패로 중단됐고, 이후 로컬 콘솔이 제공하는 차량 제어 인터페이스와 에뮬레이터 진단 테스트를 사용했다. 아래 속도·좌석 값은 테스트 더미로 대체하지 않은 실제 SDK 수신값이다.

| 콘솔 조건 | 수신값 / 결과 |
|---|---|
| P, 정차, 조수석 비탑승 | 속도 0, 운전석 미착용, 비탑승 확인. 실격 없음 |
| D, 정차, 조수석 탑승 | 속도 0, 양쪽 미착용. 실격 없음 |
| D, 10km/h, 조수석 비탑승 | 속도 약 2.778m/s, 운전석 미착용 → 운전석 실격 |
| R, 정차, 조수석 탑승 | 속도 0, 양쪽 미착용. 실격 없음 |
| R, 10km/h, 조수석 탑승 | 속도 약 2.778m/s, 양쪽 미착용 → 운전석 실격 우선 |

### 추가 콘솔 조합 검증 — 9개 통과

콘솔 제어 인터페이스로 입력하고 `SeatBeltSdkProbeTest`에서 실제 SDK 수신값을 `SeatBeltMonitor`에 전달해 비교했다. 각 조합은 새 판정기로 검사했다. 전체 경기의 저장·보상·화면까지 연속 실행한 검증과는 구분한다.

| 기어 / 속도 | 조수석 탑승 | 벨트 경고등 입력 | 실제 판정 |
|---|---|---|---|
| P / 0 | 없음 | Off | 실격 없음 |
| D / 0 | 있음 | On | 실격 없음 |
| R / 0 | 있음 | Blink | 실격 없음 |
| D / 10km/h | 없음 | Off | 운전석 실격 |
| D / 10km/h | 있음 | Off | 운전석 실격 |
| D / 10km/h | 있음 | On | 운전석 실격 |
| D / 10km/h | 있음 | Blink | 운전석 실격 |
| R / 10km/h | 없음 | Off | 운전석 실격 |
| R / 10km/h | 있음 | Off | 운전석 실격 |

모든 조합에서 운전석·조수석 체결 원시값은 `false`였고, 조수석 탑승은 입력에 맞게 바뀌었다. On/Blink에서 SDK 경고 신호는 켜졌지만 체결값은 달라지지 않았다. **경고등 Off는 벨트 착용을 의미하지 않는다.** 모든 결과에서 데이터 미확인 이력은 없었다.

재현 스크립트: `scripts/verify-seat-console.ps1` (앱 및 테스트 APK 설치 후 실행). 이번 실행 로그와 요약은 `android/app/build/seat-console-matrix/`에 보관했다. 테스트 종료 시 P·0km/h 및 원래 좌석 탑승·경고등 상태로 복원한다. 스크립트의 체결값 `false` 기대값은 현재 이미지에서 관찰한 결과이며 제품 동작의 가정이 아니다.

### 실제 콘솔에서 남은 검증

이 버전의 콘솔 기능 목록에는 좌석별 탑승 조작과 공통 Seat Belt 경고등 조작은 있지만, 운전석·조수석 각각의 **벨트 체결 조작**은 없다. 경고등 Off를 체결로 간주하지 않는다. 따라서 **운전석 착용 + 조수석 탑승/미착용** 조합과 좌석별 착용↔미착용 전환은 실제 콘솔 검증 완료라고 주장할 수 없다. 좌석별 체결 신호를 변경할 수 있는 테스트 환경에서 추가 검증이 필요하다.

이 조합들은 아래 자동 테스트에서 별도의 입력 시나리오로 검증한다. 이는 실제 SDK 조작 결과와 구분한다.

### 2026-11-14 추가 입력 경로 조사

- PC 콘솔을 `http://127.0.0.1:8088/`에 연결했고, 서버의 `browser.active=true`를 확인했다. 확인 종료 시 P, 0km/h, 조수석 비탑승 상태였다.
- 현재 Android Emulator 36.2.12 / Pleos Connect 2.1.0의 `cmd car_service help`는 `requires non-user build`로 거부됐다. 시스템 권한·보안 설정을 변경하지 않았다.
- 일반 AOSP VHAL 테스트 도구의 TCP 33452 입력 서버는 현재 기기의 리스닝 목록에 없었다. 실행 중인 차량 HAL은 Pleos 전용 서비스이며, 콘솔 서버는 DDS 시뮬레이터다.
- 설치된 에뮬레이터의 gRPC 명세와 콘솔 명령 목록에 차량 속성 입력 기능이 노출되어 있지 않았다.
- 공식 VehicleEmulatorApp은 콘솔을 표시하는 WebView 앱이었다. 콘솔 기능 목록에서 독립적인 운전석/조수석 벨트 체결 입력은 발견하지 못했다.
- Chrome에 콘솔 주소를 입력하고 이동했으나, Windows 화면 제어 도구가 URL 확인 오류로 중단되어 추가 화면 조작은 중지했다. 서버 연결 상태는 별도 콘솔 인터페이스로 확인했다.

따라서 이번 추가 조사에서도 운전석 벨트를 실제 `true`로 바꾸는 데 성공하지 못했다. 조수석 단독 미착용의 실제 연동 검증은 여전히 미완료다. Pleos가 제공하는 별도 좌석 벨트 시뮬레이션 입력 방법 또는 이를 지원하는 개발용 이미지가 필요하다. 앱 내부 테스트 값 주입을 실제 SDK 검증으로 대체하지 않았다.

## 자동 검증 범위

- 핵심 판정: 정차, D/R, 양·음수 후진 속도, 500ms 경계, 캐시/역순/오래된 관측, 조수석 빈 좌석·탑승·탑승 신호 소실, 2초 빈 좌석 확인, 미확인 이력 유지.
- 앱 통합: 예약 단계와 기록 중 실격, 즉시 저장, 결과 재조회, 보상·배지·순위 제외, 데이터 단절 감시.
- 저장/화면: 실격 및 확인 불가 목록·상세, 기존 기록 호환, 숫자 점수 및 보상 숨김.
- 기존 급가속·급감속·제한속도 채점과 정상 경기 보상 흐름의 회귀 검증.

- 중간 일괄 실행은 에뮬레이터 시스템 종료로 중단됐다. 복구 후 나눠 재실행했다. 개최지 배정 테스트는 동일 사용자의 두 번째 당일 참가를 시도하던 데이터를 서로 다른 참가자로 분리한 뒤 통과했다. 제품의 하루 한 경기 제한은 유지했다.
- 위 벨트 조합은 앱에 관측값을 주입하는 자동 검증이다. 실제 SDK에서 운전석 착용값을 바꾸거나 조수석만 미착용으로 전환하는 검증이 완료됐다는 의미는 아니다. 실제 콘솔 제약은 위 미검증 항목과 동일하다.
- 실행 로그·참가 팝업 캡처는 `android/app/build/verification/daily/merge-*` 및 `challenge-entry-belt-*.png`에 보관했다.

독립 벨트 체결 조작이 필요한 실제 콘솔 검증은 위 제한사항 때문에 미완료다. 전체 안전벨트 하드웨어 검증이 끝났다고 볼 수는 없다.
