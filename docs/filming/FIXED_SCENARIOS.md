# Pleos 최종 시연 및 검증

기준 main: `7ee175b`. 시연 영상은 디버그 Pleos 에뮬레이터에서 촬영한 편집본이다. 실제 서버 참가자·실차 검증이나 제휴 쿠폰 발급을 의미하지 않는다.

## 빌드와 데이터 분리

```bash
cd android
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug -Pfilming=true
```

`-Pfilming=true`인 debug만 `h1-filming-fixed-v1` 프로필을 사용한다. 일반 debug와 release는 기존 `h1-demo-v1`을 유지하며 release의 `FILMING_BUILD`는 항상 false다. 디버그 명령 수신기는 debug manifest에만 등록된다.

고정 시작 데이터는 2026년 11월 9~12일 하루 3건 정상 기록(08:00/12:00/16:00), 6·8·13일 실격 각 1건으로 총 15건/7개 날짜다. 장소명에는 시연 접두사를 붙이지 않지만 내부 `fixed-history` ID를 유지한다. 점수는 ScoreEngine으로 생성한다. 유효 참가 날짜 4일, 지갑 0M이 기준이다. 다섯 번째 유효 참가 시 첫 발걸음 배지로 15M을 지급한다.

촬영 빌드의 비교 참가자 점수는 92·89·86·82로 고정되어 있다. 운전자의 실제 점수는 바꾸지 않는다. 기존 기록의 비교 순위를 보강할 때도 기록·잔액·배지 보상을 재정산하지 않는다. 과거 기록의 순위별 배분액과 실제 적립액은 따라서 다를 수 있으며 상세 화면에 구분되어 있다.

## 반복 준비

정차/P 상태에서 다음을 실행한다. 위치·알림 권한이 필요하면 에뮬레이터에서 허용한다.

```bash
./scripts/pleos-filming.sh prepare
./scripts/pleos-filming.sh status
```

`prepare`는 올바른 filming APK와 주차·비주행 상태를 확인하고, 현재 촬영 프로필을 `outputs/fixed-filming/backups`에 백업한 다음 그 프로필만 초기화한다. 앱 전체 데이터 삭제는 하지 않는다. 앱 재시작만으로 기록이 초기화되지 않는다.

콘솔 Safety → Telltales → Seat Belt에서 On은 미착용 경고, Off는 착용으로 해석한다. 이 우선 처리는 명시적으로 `enable`한 디버그 Pleos 에뮬레이터(`ranchu`/`crp_avd`)에서만 적용된다. 재시작 후 On→Off로 전환해 실제 경고등 입력을 관측시킨다.

## 세 가지 챌린지 흐름

1. **목적지가 개최지에서 먼 경우**: 검색창에 한 글자씩 입력 → 추천 장소 선택 → 개최지 없음/일반 길 안내 확인 → 내장 내비. 챌린지 점수·보상은 발생하지 않는다.
2. **급가속·급감속을 반복한 경우**: 배지 4/5·0M 확인 → 미착용 상태로 참가 시도 → 콘솔 벨트 Off → 참가 → 내장 내비 → 10km 진입 음성 → 실제 콘솔 ACCEL/BRAKE 반복 → 도착/P → 종료 음성·알림 → 내 기록·배지 5/5·15M 확인.
3. **주행 중 벨트를 해제한 경우**: 지도 확대 후 개최지 선택 → 벨트 Off로 참가 → D단 주행 중 벨트 On → 실격 → 정차/P → 종료 음성·알림·실격 기록 → 배지 4/5·0M 유지 확인.

각 챌린지 촬영 전 `prepare`로 동일한 시작 조건을 만든다. 실격도 당일 참가를 사용한다.

```bash
./scripts/pleos-filming.sh enable
./scripts/pleos-filming.sh status       # 참가 후 phase=RESERVED
./scripts/pleos-filming.sh 10km-live    # 접근 표본을 추가하지 않는 실제 콘솔 평가
# 콘솔 D, ACCEL/BRAKE. 유효 판정을 위해 최소 9km 실제 콘솔 주행.
./scripts/pleos-filming.sh arrive
# 콘솔에서 완전 정차 후 P
./scripts/pleos-filming.sh notifications
./scripts/pleos-filming.sh export
```

`10km-live`/`arrive`는 앱의 디버그 신호이며 내장 내비 GPS를 이동시키지 않는다. 별도 `10km` 명령은 촬영 빌드에서 약 9km의 고정 접근 표본을 추가하는 빠른 리허설용이다. 최종 ②는 `10km-live`로 실제 콘솔 표본을 평가했다. 제한속도 미수신 시 촬영 리허설에 한해 80km/h를 시험값으로 사용한다. GPS가 없으면 방향지시등 회전 판정은 보류된다.

콘솔 반복 조작 횟수와 판정 이벤트 횟수는 같지 않다. 임계값·연속 구간 및 첫 10km 평가 범위를 적용한 최종 ② 결과는 **61점·급가속 6회·급감속 5회·5위·순위 보상 0M·배지 보상 15M**이다. 조작 횟수 n/7 자막은 제거했다.

음성:
- 진입: “마지막 십 킬로미터입니다. 무사즈 기록을 시작해요.”
- 정상 종료: “무사히 도착했어요. 무사즈에서 주행 결과를 확인해 주세요.”
- 실격/P: “주행이 종료됐어요. 안전벨트 미착용으로 실격됐어요. 무사즈에서 주행 결과를 확인해 주세요.”

장시간 캡처에서 누락된 종료 장면은 `announce-saved-result`로 실제 저장된 결과의 음성·알림을 다시 재생해 연결했다. 이 명령은 촬영 debug/P/비주행 상태에서만 가능하고 정산을 반복하지 않는다. 영상은 연속 단일 촬영이 아닌 편집본이다.

## 기능별 추가 촬영

- 내 기록: 주간 날짜 드래그, 최신순/오래된순, 월간 달력, 11월 12일 16:00 현대 모터스튜디오 고양(87점/3위/+0M)의 점수·순위·마일리지 상세.
- 마일리지: 촬영 프로필 백업 후 `balance-live`를 100으로 설정 → 가장 저렴한 와이퍼 80M 교환 → 잔액 20M·쿠폰함 번호 저장. 필터/오일 상세·부족 잔액·사용처·오일 교환권 안내 확인. 교환은 기존 demo 또는 filming debug에서만 허용한다.
- 배지: 전체 22개 상세와 버튼을 실제로 테스트했지만 최종 영상은 약 42초로 축약했다. 출석 도장의 획득/진행 배지 각 1개만 열고, 명예 훈장은 스크롤, 스팟 투어는 목록으로 확인한다. 진행 단계 표시는 기존 달성 예시보기이며 실제 적립 이력을 새로 만들지 않는다.
- 마이페이지: MUSAZ를 한 글자씩 입력해 저장, 변경 취소, 사용법 다시 보기의 다음/이전/완료/건너뛰기, 차량 상태 확인. 차량 상태와 내 기록 우측 습관 요약 카드는 별도의 상세 클릭 기능이 없다.

앱 재시작 후에도 MUSAZ·20M·와이퍼 쿠폰 유지 확인. 원본 15개 기록과 배지 진행 데이터는 보존됐다. `prepare`를 실행하면 다시 0M/4일 기준으로 돌아간다.

## 최종 검증 결과

- `:core:test`: 170개 통과, 실패·오류 0.
- `:app:testDebugUnitTest`: 50개 통과, 실패·오류 0.
- filming debug APK 및 AndroidTest APK 빌드 성공. Pleos 사용자 10에서 `FilmingDataTest` 1개 통과(별도 임시 테스트 프로필만 사용).
- `:app:assembleRelease -Pfilming=true` 성공. 생성된 release BuildConfig의 DEBUG/FILMING_BUILD=false 및 병합 manifest에 리허설 수신기 없음 확인.
- 리뷰에서 발견한 빈 추천 결과의 내장 내비 검색 fallback 및 이전 주행의 지연 종료가 새 기록에 영향을 주는 문제 수정·재검토 완료.
- 실제 콘솔·앱 UI 검증과 고정 비교 데이터는 위에 구분했다. 실차 및 서버 순위/제휴 쿠폰은 검증하지 않았다.
