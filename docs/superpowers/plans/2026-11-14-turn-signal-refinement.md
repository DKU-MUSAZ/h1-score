# 방향지시등 판정 및 콘솔 검증 계획

**Goal:** 조향 부호를 교정하고 좌우회전 신호 시점·보류 사유를 보완하며 차선변경 후보를 별도로 기록한다.
**Architecture:** 차량 SDK 입력은 공통 좌표계로 변환한다. 코어는 시간순 신호·GPS·내비 증거를 평가하고, 결과에 동작 종류와 보류 사유를 저장한다. 차선변경은 도로/차로 근거가 없으므로 우선 관찰 전용이며 감점하지 않는다.
**Tech Stack:** Kotlin, Android Automotive/Pleos 2.3.2, JUnit, 콘솔 HTTP 제어 및 계측 테스트.
**Spec:** 이 채팅에서 승인한 개발 순서. 실제 콘솔 수신과 모의 경로 검증을 구분한다. 기존 격리 브랜치를 유지한다.

## 제약과 판단
- 급가속·급감속·제한속도 수식과 카카오/내비 목적지 연결은 변경하지 않는다.
- 좌우회전 미사용 -1, 반대방향 -2, 총 -10 상한 유지. 늦은 사용은 사전 미사용(-1)으로 분리한다.
- 신호는 시작 전 3초 중 최소 500ms의 연속된 신선한 관측으로 확인한다. 반대방향을 계속 켜다 회전 후 수정한 경우 정상으로 덮지 않는다.
- 조향은 Pleos SDK의 양수=좌측을 코어 음수=좌측으로 정규화. 원시값은 유지한다.
- 정상 좌우회전은 2~25m/s, GPS 정확도 10m/방위 정확도 15도 이내. 핸들 범위는 ±540도, 시작 5도·중립 2도. 내비 맥락 유효기간은 3초에서 10초로 늘리되 거리 40m 이하 조건 유지.
- 차선변경 후보는 신선한 고정밀 GPS(정확도 1m 이하), 5~25m/s, S자 조향, 2초 이상 전후 안정 진행방향, 2.5~5m 횡변위, 최대 10도 진행방향 복귀로 제한한다. 반대 조향/곡선/오차 사례를 테스트하고 도로 문맥 미확인으로 기록한다. 차선 존재를 확정하거나 보상에 반영하지 않는다.
- 데이터 누락은 정상 운전으로 표시하지 않는다. 현재 회전 관측 상태 및 사유를 기록하고 결과에도 남긴다.

## 검토 초점
- 원시값과 정규화값 혼동, 좌우 부호 반전.
- 캐시/순서역전 콜백이 사전 신호 지속시간이나 조향 지속시간을 만드는 경우.
- 비상등/양방향/짧은 사용이 정상으로 인정되는 경우.
- 회전과 차선 후보 중복 감점, GPS 부족을 정상으로 잘못 설명하는 경우.
- 저장된 구버전 기록의 점수/설명이 새 버전으로 바뀌는 경우.
