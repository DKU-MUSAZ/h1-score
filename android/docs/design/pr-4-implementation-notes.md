## 1. 주행 이벤트 검출

소스: [ChallengeRules.kt](../../core/src/main/kotlin/ai/musaz/h1score/core/ChallengeRules.kt)의 `ScoreEngine.evaluate`, `DrivingEvent`, `ScoreReport`.

입력은 시각·차량 속도(m/s)·제한속도(km/h)를 가진 연속 샘플입니다.

1. 인접 샘플의 시간 차 `dt`를 구합니다. `dt <= 0`인 쌍은 건너뜁니다.
2. `dt > 2.5초`, 속도 누락·비정상 값, 속도 범위 0~80m/s 이탈, 제한속도 범위 1~150km/h 이탈은 유효 구간에서 제외합니다. 이때 연속 이벤트 상태도 초기화합니다.
3. 구간 거리는 `(이전 속도 + 현재 속도) / 2 × dt`로 계산합니다.
4. 아래 조건에 진입하는 순간을 이벤트로 남깁니다. 조건이 계속 유지되는 동안에는 같은 종류의 이벤트를 반복 저장하지 않습니다.

| 이벤트 | 조건 | 현재 점수 처리 |
| --- | --- | --- |
| 제한속도 초과 | 현재 속도 × 3.6 > 제한속도 | 초과 정도와 구간 거리를 기존 점수 계산에 반영 |
| 급가속 | (현재 속도 - 이전 속도) / dt > 2.5m/s² | 해당 구간 거리를 기존 가속 점수 계산에 반영 |
| 급감속 | (현재 속도 - 이전 속도) / dt < -2.5m/s² | 참고 정보로 기록, 감점 제외 |

이벤트에는 종류, 첫 샘플 이후 경과 시간, 누적 유효 거리, 전후 속도, 제한속도를 저장합니다. 위치는 **GPS 좌표나 도로명이 아닌 유효 샘플 거리 기준의 추정 구간**입니다.

저장 이벤트는 최대 100개이고, 피드백 화면은 기록 순서상 처음 8개를 표시합니다. 저장 한도와 별개로 점수 계산·과속 거리·급가속 횟수 집계는 계속합니다. 전체 평가는 샘플 수에 비례해 처리합니다.

## 2. 기존 점수와 새 피드백의 관계

이번 PR은 점수 가중치나 가점 규칙을 새로 도입하지 않았습니다. 현재 구현의 계산은 다음과 같습니다.

- 제한속도 초과량: `max(0, 현재 속도 × 3.6 - 제한속도)`
- 과속 가중 거리: 구간별 `거리 × clamp(초과량 / 15, 0, 1)`의 합
- 제한속도 준수 점수: `clamp(100 - 과속 가중 거리 / 유효 거리 × 100, 0, 100)`
- 부드러운 가속 점수: `clamp(100 - 급가속 구간 거리 / 유효 거리 × 100, 0, 100)`
- 최종 점수: `round(제한속도 준수 × 0.7 + 부드러운 가속 × 0.3)`

유효 거리 500m 이상·시간 기준 데이터 수신율 90% 이상에서 점수를 표시합니다. 유효 기록 판정은 거리 9km 이상·수신율 90% 이상이며, 이 조건도 기존 구현입니다.

[H1App.kt](../../app/src/main/java/ai/musaz/h1score/H1App.kt)의 `ResultFeedback`은 `(100 - 준수 점수) × 0.7`, `(100 - 가속 점수) × 0.3`을 약 몇 점 감점인지 보여줍니다. 최종 점수의 반올림 때문에 표시한 감점 합과 정수 점수의 차이는 일치하지 않을 수 있습니다.

**후속 검토:** 안전점수의 감점·가점 기준을 정리하고, 그 기준에 맞춰 피드백 문구·표시 항목·구간 표시를 보완해야 합니다. 별도의 가점 기능이 이미 구현됐다고 해석하면 안 됩니다.

## 3. 주행 결과 저장과 이전 기록 호환

소스: [CompletedDriveStore.kt](../../app/src/main/java/ai/musaz/h1score/CompletedDriveStore.kt).

완료된 결과 JSON에 `events` 배열을 추가했습니다. 예전 기록처럼 배열이 없으면 빈 목록으로 복원합니다. 이전 기록은 요약 점수를 보여주되 구간 정보가 없음을 안내합니다. 저장·복원 과정에서 GPS 위치를 추가 수집하지 않습니다.

점수 다이얼은 캔버스의 짧은 변을 기준으로 정사각형 범위에 호를 그려 타원으로 늘어나는 문제를 막습니다. 참가자 순위 영역은 주요 결과 카드 아래에 배치합니다.

## 4. 마일리지 교환 확인과 쿠폰함

소스: [MileageScreen.kt](../../app/src/main/java/ai/musaz/h1score/MileageScreen.kt), [ChallengeViewModel.kt](../../app/src/main/java/ai/musaz/h1score/ChallengeViewModel.kt)의 `redeemDemoReward`, 기존 `MileageLedger.spend`.

- 로컬 혜택 목록: 와이퍼 80M, 에어컨 필터 300M, 엔진오일 600M.
- 카드 선택은 확인 창만 열며 잔액을 차감하지 않습니다.
- 취소하면 잔액과 교환 내역을 유지합니다.
- 부족 금액은 `max(필요 마일리지 - 잔액, 0)`으로 표시하고 교환 버튼을 비활성화합니다.
- 실제 처리 시에도 주차 상태, 이미 교환한 혜택인지, 잔액이 충분한지 다시 확인합니다. 조건 실패 시 차감하지 않습니다.
- 성공하면 잔액과 교환한 혜택 ID 집합을 기기에 저장합니다. 현재는 혜택별 1회 시연 교환이며 쿠폰 수량 관리나 서버 거래는 없습니다.
- 쿠폰함은 저장된 혜택 ID와 로컬 목록을 대조해 교환 내역을 표시합니다.
- 사용기한 `2031.11.11`은 요청된 **고정 시연 표시 날짜**입니다. 교환일 기준 자동 5년 계산이나 실제 만료 처리 기능은 없습니다.

사용처 지도 검색·현재 위치 수집·제휴 정비소 결제·실제 쿠폰 발급은 이 흐름에 포함되지 않습니다.

## 5. 튜토리얼 다시보기

소스: [FirstRunHost.kt](../../app/src/main/java/ai/musaz/h1score/FirstRunHost.kt), `ChallengeViewModel.restartTutorial`.

첫 설정이 완료된 사용자에게 재보기 플래그를 저장하고, 소개·동의·닉네임 화면을 거치지 않고 5개 메뉴 안내로 진입합니다. 닉네임·기존 동의·동의 시각·주행 기록·마일리지는 지우지 않습니다. 완료하거나 건너뛰면 재보기 플래그를 제거합니다.

주차 중이고 활성 주행·내비 경로 대기·스팟 기록 등의 제한이 없는 경우에만 다시보기를 시작합니다.

## 6. 마이페이지 차량 상태 조회

소스: [PleosConnection.kt](../../app/src/main/java/ai/musaz/h1score/PleosConnection.kt), [MyProfileScreen.kt](../../app/src/main/java/ai/musaz/h1score/MyProfileScreen.kt).

기존 차량 정보에 워셔액 부족 경고, 현재 주행 전비(km/kWh), 현재 주행 연비(L/100km)를 추가했습니다. 새 항목은 SDK 읽기 지원 여부를 먼저 확인합니다.

- 프로필 화면이 활성화된 동안 조회하고, 조회 후 2초를 기다려 다시 읽습니다.
- 추가 프로필 조회는 병렬로 요청하며 개별 요청은 1.5초 타임아웃을 적용합니다.
- 배터리·연료는 0~100 범위, 각도는 유한 값, 전비·연비는 유한한 0 이상 값만 표시합니다.
- 실패·미지원·미수신은 임의 값으로 채우지 않고 '미확인'으로 처리합니다.
- 앱 시연 모드에서는 실제 차량 상태를 표시하지 않습니다.

마이페이지 정보 배치와 시각적 구성은 후속 UI 개선 대상으로 남깁니다.

## 7. 현재 위치와 내비 목적지의 구분

기존 [VenueMatching.kt](../../core/src/main/kotlin/ai/musaz/h1score/core/VenueMatching.kt)는 Haversine 방식으로 두 좌표 사이의 직선거리를 계산합니다. `nearestEligibleVenue`는 **현재 차량 위치가 아니라 내비 목적지**를 기준으로 반경 1km 안의 가장 가까운 챌린지 개최지를 선택합니다. 거리가 같으면 개최지 ID로 결정합니다.

이 코드는 이번 PR에서 새로 추가한 마일리지 사용처 탐색 알고리즘이 아닙니다. 현재 위치 기반 탐색에서는 별도의 현재 위치 공급과 사용 가능한 제휴 매장 목록이 필요합니다.
